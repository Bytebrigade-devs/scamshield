# M4-04 draft rule analysis — refined 24 October 2026

**ID namespace:** `R-M4-xx` IDs in this document are catalogue rule-hypothesis IDs (`R-M4-01…20`), not the Final report's requirement IDs (`R-M4-01…18`). The series are unrelated — e.g. catalogue `R-M4-13` is the prize/reward claim-link rule, while report `R-M4-13` is the own-history requirement (SRS `FR-M4-13`).

**v0.6-draft Singlish corroboration requirement — 20 November 2026 (workspace-only):** **no rule may rest on romanised Sinhala ("Singlish") tokens alone.** On the owner's instruction ("do not trigger scan just based on the singlish word, because it is not accurate. combine them with other rules"), a match whose **entire cue evidence** is Singlish tokens plus neutral characters (digits, punctuation, URLs) is reported **only when another match on the same message carries independent evidence**. Shape flags (R-M4-18/19/21/22/23) count as corroboration — they are host/attachment evidence, not romanised vocabulary. **Why:** Singlish has no standard spelling (`dakwa`/`dakva`, `naya`/`nayak`, `rina`/`rin` are variants of the same words) and several tokens are ordinary vocabulary (`karanna`, `danma`, `rin`), so a romanised token is a weak signal. `selectEvidence` now **prefers a non-Singlish-only evidence set**, so a message carrying both romanised and English/Sinhala evidence is judged on its stronger evidence rather than on whichever anchor came first in the text. **Sinhala-script cues are deliberately NOT treated as weak** — the script is unambiguous, unlike romanisation. **Measured effect: 500-set and frozen fixture both UNCHANGED** (0 records gained, lost or changed; per-language scam detection 54/175 English, 12/105 Sinhala, 11/70 Singlish, identical before and after). The gate bites only on **purely-Singlish inputs**, where it removes **3 of the 5 adapted v0.4 loan cases** — a deliberate **precision-over-recall** decision, recorded rather than hidden. **Verification (Node v24.22.3): rule-engine 75/75 (68 + 7 new), workspace 544/544, strict sweep 103/103, zero mismatches, one review-required (`M4-OT08-S`, unchanged).** No rule ID or arity changed; frozen fixture unmodified.

**v0.5-draft Singlish "karanna" gate — 20 November 2026 (workspace-only):** the bare Singlish verb **`karanna`** (Sinhala කරන්න, "to do") is no longer evidence on its own. It was carried inside `CLAIM_DEMAND_RE` and could fire **R-M4-13** as a claim demand by itself. That was wrong in both directions: the token appears in **40 of the 100 `singlish_mixed` records** (7 of them controls) because it is an ordinary verb — "renew karanna", "call karanna", "check karanna" — and it fired R-M4-13 on a genuine promotion linked to the bank's own reviewed domain (`…prize draw ekak karanna… https://www.sampath.lk/promotions`), which is **exactly the reviewed-official-domain false positive the v0.3 rules exist to avoid**. The token now counts only when the message also carries a destination that is **not** a reviewed official host. This is an **unreviewed-destination gate, never a maliciousness claim**: a genuine but unlisted promotion containing the verb and a link still fires (documented limitation, same tradition as R-M4-20's link requirement). When no parseable URL is present the gate does not apply, so phone/email destinations keep their previous behaviour. The gate matches on the **cue value**, so English claim wording and Sinhala `තහවුරු කරන්න` are unaffected. **No rule ID, arity, threshold or honesty boundary changed; R-M4-01…12 and R-M4-14…23 are untouched.** Measured effect: 500-set **unchanged** (still one R-M4-13 detection where `karanna` supplies the excerpt, `M4-500-190`, a scam; **0** non-scam records affected, and **0** corpus records pair `karanna` with a reviewed official link); frozen fixture **unchanged** (M4-SL10-S still fires, M4-SL10-L still silent); the failure mode is closed by construction and pinned by 5 new regression tests. **Verification (Node v24.22.3): 68/68 rule-engine tests (63 pre-existing + 5 new), workspace suite 532/532, strict sweep 103/103 evaluated, zero mismatches, one review-required (`M4-OT08-S`, unchanged).** Frozen fixture not modified; its SHA-256 (`db2b9596…f7e2d6`) is unchanged.

**v0.4-draft R-M4-20 cue amendment — 20 November 2026 (workspace-only):** three cue regexes widened after an owner-supplied batch of **13 real messages** (10 scam / 2 legitimate telco promos / 1 inconclusive remittance teaser) showed R-M4-20 firing on only **3 of the 10 scams**. `LOAN_CTX_RE` gains the romanised debt/loan words `naya`/`nayak`/`rina`/`rin` and the `dakva` spelling variant of `dakwa`; `LOAN_AMOUNT_RE` gains the `rupiyal` prefix and an optional trailing `k` thousand suffix while **preserving its 6-character bare-amount floor**; `DESTINATION_RE` accepts a schemeless domain carrying an explicit path segment (`cashx.lk/sl/qh` shape). **No new rule ID, no arity/threshold/honesty-boundary change; R-M4-01…19 and R-M4-21…23 are untouched.** Coverage: real batch **3/10 → 9/10** with **0/2** legitimate flagged; frozen fixture **0/52 → 0/52** false positives; 500-set **7/350 → 8/350** with **0/150** false positives (the gain is a genuine authored scam). ## Interfaces and matching

- `analyzeRules(text)` returns `{ matches: [{ ruleId, excerpt, start, end, contextNote }] }`. `start` is inclusive and `end` exclusive, measured in JavaScript UTF-16 code units in the original input. `text.slice(start, end) === excerpt`, including repeated phrases and Unicode before a match.
- Evidence is selected from the qualifying cue pair, rather than the first keyword anywhere in the message. Secret/request pairs share a punctuation and instruction scope; contrast and consequence markers such as “but” and “so” end an earlier prohibition's scope.
- Related context cues may span nearby sentences within a draft 320-character window. Explicit topic changes cannot supply cues or suppress an unrelated request. Secret/request and job/payment pairs retain the draft 80-character proximity; prize/payment evidence can span 160 characters across nearby clauses. These are local matching heuristics, not input limits or validated efficacy thresholds.
- Fee/credential nouns use a narrower negation guard than action verbs. “Cannot confirm your entry until the fee arrives” does not negate the fee. An explicitly ignored supplier record cannot suppress an invoice demand.
- Wording covers additional documented romance, card-information, job-fee and cheque/onward-transfer variants. Tests also distinguish depositing a cheque from paying an upfront job fee.
- `checkDisplayTarget(display, target)` remains a metadata-only draft comparison. Its offsets reference the supplied target string, not the message. URL reputation, canonicalization and domain verification are not implemented.

Both analysis functions perform no network I/O. Treat excerpts as untrusted text when later rendering them; escaping and bidi/control-character display safeguards still belong to that future stage.
